# ViewScope 1.3 设计：iOS 宿主支持、逻辑修复与增强调试工具

日期：2026-10-16

## 1. 目标

1. 修复三份审计（服务端、客户端核心、预览/层级树）列出的逻辑错误与半成品功能。
2. 新增 iOS 宿主支持：iOS 模拟器（loopback 端口扫描）与 iOS 真机（usbmuxd 隧道）。
3. 新增 Reveal / Lookin 不具备的调试能力：
   - 测量与对齐：两节点间距标注、光标坐标读数、取色器。
   - 布局问题诊断：歧义布局、被裁剪/越界、零尺寸容器、非整像素 frame、透明却拦截事件、被不透明兄弟完全遮挡、文本截断、图片放大模糊、过小点击区域。
   - 修改记录与快照对比：实时修改日志、撤销/逐条还原、导出为代码；两次抓取之间的层级 diff。
   - 控制台增强：带参数方法、key path、对象引用参数、历史记录、自动补全；修复会让宿主崩溃的实现。

## 2. 代码约定（所有实现者必须遵守）

- `if` / `else` / `switch` / `guard ... else` / 循环必须使用大括号，受控语句另起一行；左大括号放在行尾。
  - 正确：`guard let x else {\n    return\n}`；错误：`guard let x else { return }`、`if a { b }` 单行写法。
  - 新增与修改的代码遵守；未改动的旧代码不必批量重排。
- 注释使用中文，准确说明逻辑。
- 只有给系统/第三方类加扩展方法或属性时才加 `kg_` 前缀；本工程自有类型不加。
  - 例外：已有的 `viewScope` 前缀扩展保持原样，不重命名。新增的系统类扩展成员使用 `kg_` 前缀。
- 禁止运行 `xcodebuild`、`swift build`、`swift test`、`pod install/update`、`carthage`。
- 允许且鼓励：`swiftc -parse` / `swiftc -typecheck`（输出目录只用 `/tmp`），`plutil -lint`。
- 不要 `git commit`，不要改动 git 状态。
- 只修改自己拥有的文件；需要别人的文件配合时，在最终报告里说明。

## 4. 协议 v3（已写入 `ViewScopeBridge.swift`）

### 4.1 版本协商

- `viewScopeCurrentProtocolVersion = 3`，`viewScopeMinimumSupportedProtocolVersion = 2`。
- 客户端 `clientHello.protocolVersion = min(3, announcement.protocolVersion)`。
- 服务端接受 `2...3`，`serverHello.protocolVersion` 与 `serverHello.host.protocolVersion` 回填协商结果 `min(client, 3)`。
- 客户端对协商版本 `< 3` 的宿主不发送 v3 新消息（console 补全、ping）。

### 4.2 发现

- 服务端在 `127.0.0.1` 上依次尝试绑定 `viewScopeHostPortRange`（47300...47339）中第一个空闲端口。
  - macOS：全部失败时退回 `.any`，并继续通过 `DistributedNotificationCenter` 广播 announcement（保持向后兼容）。
  - iOS（模拟器和真机）：只走端口段；全部被占用时记录日志并放弃。
- `discoveryRequest`（无需认证）→ `discoveryResponse`，`message.announcement` 为宿主 announcement（含 authToken，loopback 环境下可接受）。
- 客户端：
  - macOS 通知：保留。
  - loopback 扫描：每 2 秒扫描一次端口段，单次探测超时 1 秒。
  - usbmuxd：监听设备接入/拔出；对每台设备每 3 秒扫描端口段；发现的 announcement 由客户端改写 `identifier = "\(deviceSerial)|\(原 identifier)"` 并填写 `transport = .usbmux(...)`。
  - 同一 identifier 多来源合并；探测失败时保留 15 秒宽限期（宿主停在断点时不立刻消失）。
- 服务端必须支持“已有已认证会话时，再来一个探测连接”：探测连接不得踢掉已认证会话。只有新的连接 **完成认证** 之后，才替换旧的已认证会话。

### 4.3 连接与请求

- 每个连接独立维护 `isAuthenticated`；未认证连接只允许 `clientHello`、`discoveryRequest`、`ping`，其余请求回 `.error`。
- 带 `requestID` 的请求必须恰好得到一条响应：未知 kind、缺少 payload、节点不存在都回 `.error`。
  - 无法解码的行：用 `JSONSerialization` 尽量取出 `requestID` 后回 `.error`。
- 编码时把 NaN/Inf 清洗为 0（或使用 `nonConformingFloatEncodingStrategy`），保证 capture 不会因为一个非有限数整个发不出去。
- `ping` → `ack`。
- 旧连接的 `onDisconnect` 只在它仍是当前会话时才清空会话引用。

### 4.4 节点

- 节点 ID 跨抓取稳定：`"\(kind.rawValue)-\(十六进制对象地址)"`，例如 `layer-0x600001234560`、`window-0x7f8...`。
  - 共享 helper：`ViewScopeNodeIdentity.nodeID(kind:object:)`（S-core 实现于 `Sources/ViewScopeServer/ViewScopeNodeIdentity.swift`）。
  - `previewBitmaps[].rootNodeID`、`detail.screenshotRootNodeID` 都使用新 ID。
- 节点结构保持现状：layer-backed 视图仍是 `.layer` 节点并带 `hostViewClassName`；纯 CALayer 是不带 `hostViewClassName` 的 `.layer` 节点；无 layer 的 AppKit 视图是 `.view` 节点；窗口是 `.window` 节点，其唯一子节点是窗口根视图（macOS：theme frame；iOS：UIWindow 自身）的 layer 节点。
- **带宿主视图的 layer 节点**：
  - detail 使用宿主视图的完整分区（Identity / Layout / Rendering / Control / 各控件专属分区）外加 layer 专属项（masksToBounds、cornerRadius、borderWidth/borderColor、shadow 等）。
  - constraints 取宿主视图。
  - mutation：视图级 key（hidden、alpha、frame.*、bounds.*、backgroundColor、控件专属 key）路由到宿主视图；`layer.*` key 作用于 layer。
  - console targets：layer、宿主视图、**精确**拥有该视图的 VC（`controller.view === hostView`）。
- `traits: ViewScopeNodeTraits?`：尽量为所有 view/layer 节点填写（见 `ViewScopeBridge.swift` 注释）。
- 坐标：`node.frame` 是相对 preview root（窗口根节点）的左上角原点画布坐标，单位 point；iOS 天然左上原点，直接 `convert(_:to: window)`；`isFlipped` 在 UIKit 下恒为 `true`。
- 枚举型可编辑属性使用 `ViewScopeEditableProperty.enumeration(key:value:options:)`。

### 4.5 Console

表达式语法（服务端解析与执行，客户端不再做 `:`/`.` 拦截）：

```
expression := [keyPath "."] message
keyPath    := identifier ("." identifier)*      // 每段都是零参 getter，返回对象
message    := identifier                        // 零参方法或属性
            | (keyword ":" argument)+           // 例：setHidden:YES、setFrame:{0,0,100,40}、insertSubview:@0x1234 atIndex:0
argument   := number | YES | NO | true | false | nil
            | "string"（支持 \" 与 \\ 转义）
            | #RRGGBB / #RRGGBBAA                  // 转为平台颜色对象（NSColor / UIColor）；参数类型为 CGColorRef 时转 CGColor
            | {x, y} | {w, h} | {x, y, w, h}       // 按参数类型编码为 CGPoint / CGSize / CGRect
            | {top, left, bottom, right}          // 参数类型为 NSEdgeInsets / UIEdgeInsets 时
            | @<objectID>                          // 引用 console 返回过的对象或当前 target 列表中的对象
```

- 执行：ObjC 层 `ViewScopeConsoleInvoker`（放在 `ViewScopeServerBootstrap` 目标中，`.h/.m`），使用 `NSMethodSignature` + `NSInvocation`，`@try/@catch` 捕获 NSException。
- 拒绝：`dealloc`、`release`、`retain`、`autorelease`、`retainCount`、`zone`、`self` 以外的内存管理 selector；以 `init`/`new`/`copy`/`mutableCopy` 开头的 selector（避免所有权混乱）。
- 返回值装箱：`id`、`Class`、BOOL/char、各整数、float/double、`SEL`、`void`、`CGRect`/`CGPoint`/`CGSize`/`NSRange`/`CGAffineTransform`/`NSEdgeInsets`/`UIEdgeInsets`；其他类型返回明确错误。
- 返回对象缓存：最多 64 个（LRU，强引用），`stop()` 时清空；`objectID` 为十六进制地址。
- `consoleCompletionRequest` → `consoleCompletionResponse`：列出目标类继承链（不含 `NSObject` 本身）的属性与实例方法，按 prefix（不区分大小写）过滤，最多 500 条，属性在前。

## 6. 客户端约定

- `WorkspaceSessionProtocol` 新增：`negotiatedProtocolVersion`、`setUnexpectedDisconnectHandler(_:)`、`requestConsoleCompletions(target:prefix:)`（均有默认实现）。
- `ViewScopeClientSession(announcement:)` 依据 `announcement.resolvedTransport` 选择 loopback（NWConnection）或 usbmux 传输。
- 请求超时：建连 5 秒；普通请求 15 秒；capture 30 秒。超时抛出可本地化错误，不断开连接（capture 超时除外由 store 决定）。
- `DiscoveryCenter.announcements` 仍是对外唯一数据源；另提供 `@Published usbDevices: [ViewScopeUSBDevice]`（名称、序列号、连接类型），供界面展示“已连接设备但未发现宿主”的提示。
